## 实现结论

- 默认预算改为 16 records、32 mentions、12,000 完整请求预计输入 token、4,500 预计输出 token。
- 分片策略升级为 `entity-convergence-shard-v2`，完整 `EntityMemoryRecord` 仍是不可拆原子。
- 输入估算由 payload-only 改为“序列化 payload + Provider system prompt/JSON Schema 固定开销”；自定义 Provider 缺少该指标时使用保守的 1,024-token 开销。
- 输出估算保持 mention ID 实际长度加每 record 192 token；192 来自完整覆盖批次约 190 token/record 后向上取整。
- Trace/Inspector/UI 新增 record 预算、最大 shard records、输入估算策略和固定开销；不记录姓名、正文或 evidence quote。
