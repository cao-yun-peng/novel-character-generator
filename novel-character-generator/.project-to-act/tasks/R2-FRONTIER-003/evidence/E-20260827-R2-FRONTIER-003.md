## 解决的问题

1. 历史 unresolved 不再在每个十章批次重复提交，避免输入与强制输出随全文单调增长。
2. 文末只有少量新 Chunk 时，不再自动把全文所有旧 unresolved 塞进尾批。
3. Provider omission 在保守补成 `keep_unresolved` 之前被单独计量，运行成功不再掩盖原始输出不完整。
4. Frontier 可由数据库中的 batch packet 重建，不增加恢复时易丢失的进程内 dirty 状态。

## 未覆盖与下一步

- 单个当前 frontier 仍可能过大；尚未按 mention 数和预计输出 token 分片。
- Provider omission 仍由保守补全降级；尚未做 continuation/repair。
- stable memory 仍全量作为 confirm_link 上下文，后续可按 frontier 检索候选。
- 长期没有新证据的 deferred unresolved 不会自动文末重试；后续应设计有界、分片的 final sweep。
